### Content-filter fallback

A request whose provider's content filter blocks it (`finish_reason: content_filter`, or an error with `code: content_filter`) is made once more on the same model on another provider, where `AGENT_CONTENT_FILTER_FALLBACKS` names one (`from=to`, comma-separated; empty for none). The default sends `azure/deepseek-v4.1-flash`, whose Prompt Shields filter blocks ordinary coding answers as jailbreaks, to `openrouter/deepseek/deepseek-v4.1-flash-1017:nitro`. The fallback uses the agent's key for that provider (its key scope's entry, or the account's key), and is made inside the same model request, before Pi sees the block: history keeps only the fallback's answer, and a watcher sees the response begin again (a new `message_start`). Each attempt is billed as its own model call: the blocked one at the blocked model's price on its key, the fallback at its own. A failure of the fallback is the request's failure, retried as any other (on the agent's own model first). The next request goes to the agent's own model. Only agents whose key is resolved per call (a key scope, or the platform's Azure) fall back. Each fallback is a `model_fallback` metric line (`ModelFallbacks` by `From`, `To` and `Reason`).
